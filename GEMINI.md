### ОБЗОР ПРОЕКТА
Этот проект представляет собой Telegram-бота, разработанного с использованием фреймворка `aiogram`. Бот предназначен для мониторинга цен, хотя основная логика еще не реализована. В проекте используется `pydantic` для управления конфигурацией и `aiosqlite` для асинхронной работы с базой данных SQLite (в будущем). Особенностью является настроенная работа через прокси-сервер.

**Ключевые технологии:**
- **Фреймворк бота:** `aiogram`
- **Управление конфигурацией:** `pydantic-settings`
- **База данных:** `aiosqlite` (планируется)
- **Асинхронные запросы:** `aiohttp`

### СТРУКТУРА ПРОЕКТА
- `main.py`: Точка инициализации бота и диспетчера `aiogram`.
- `run_bot.py`: Главный скрипт для запуска бота.
- `config.py`: Загрузка конфигурации (токен, прокси) из `.env` файла.
- `handlers/`: Директория для обработчиков сообщений и команд.
- `core/`: Директория для бизнес-логики, включая работу с базой данных (`database.py`) и модели данных (`models.py`).
- `keyboards/`: Директория для клавиатур Telegram.
- `pyproject.toml`: Файл с зависимостями проекта.

### ЗАПУСК И РАЗВЕРТЫВАНИЕ
1.  **Создайте и настройте окружение:**
    ```bash
    # Установите uv (если не установлен)
    pip install uv
    # Создайте виртуальное окружение
    uv venv
    # Активируйте окружение
    source .venv/bin/activate
    ```

2.  **Установите зависимости:**
    ```bash
    uv pip install -r requirements.txt
    ```

3.  **Создайте файл `.env`** в корне проекта и добавьте в него следующие переменные:
    ```
    BOT_TOKEN="YOUR_TELEGRAM_BOT_TOKEN"
    PROXY_URL="socks5://user:pass@host:port"
    ```

4.  **Запустите бота:**
    ```bash
    python run_bot.py
    ```

### ПРИНЯТЫЕ СОГЛАШЕНИЯ
*   **Форматирование**:
    *   Лимит строки: 100 символов.
    *   Отступы: 2 пустые строки между классами/функциями верхнего уровня, импортами.
    *   Язык: **Только Русский** (docstrings, комментарии, логи, сообщения об ошибках).
*   **Pydantic DTO**:
    *   `Field` должен содержать `examples` и `description`.
    *   Необязательные поля объявляются как `type | None = Field(None)`.
    *   Для каждой модели указывать краткую, информативную **docstring-строку** (в первой строке под объявлением класса).
*   **Python**:
    *   Используй встроенные дженерики: `list[str]`, `dict[str, int]`, `type | None` (вместо `Optional`, `List`, `Dict`).
    *   Используй `match/case` где это уместно.
*   **Логика**:
    *   Обработчики (`handlers`) должны быть максимально "тонкими". Основная бизнес-логика выносится в директорию `core`.
    *   Взаимодействие с базой данных происходит только через функции в `core/database.py`.
