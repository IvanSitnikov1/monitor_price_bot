# Стиль кода проекта

## Общие правила

- Максимальная длина строки — 100 символов.
- Между импортами и классами или функциями верхнего уровня используй 2 пустые строки.
- Все docstring, комментарии, логи и сообщения об ошибках пиши только на русском языке.
- Не начинай наименования функций с "_", если они испльзуются только в текущем файле. Так можно делать только внутри класса.
- Пиши короткую информативную docstring к каждой функции.
- Если требуется написать фрагмент кода до 5 строк, который повторяется менее чем 2 раза не выноси его в отдельную функцию.
- Избегай избыточых проверок в коде. Не нужно проверять данные, если они уже явно проверены выше по стеку вызовов.

## Pydantic DTO

- Каждый вызов `Field` должен содержать `examples` и `description`.
- Необязательные поля объявляй в формате `type | None = Field(None)`.
- Для каждой модели указывай краткую информативную docstring первой строкой под объявлением класса.
- Для внешних полей, которые отправляют и получают внешние сервисы нужно делать alias в camelCase. Внутри python кода нужно придерживаться snake_case.

## Python

- Для типизации используй встроенные обобщённые типы: `list[str]`, `dict[str, int]` и др. (type | None)` вместо устаревших вариантов Optional`, `List` и `Dict` без отдельной причины.
- Используй `match/case` и тернарный оператор ":=" когда это делает код понятнее и уместно для задачи.
- В python строках предпочтительно использование одинарных кавычек.
