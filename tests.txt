Логика работы многопользовательского режима (требует тестирования):

1. Добавление товара:
   - Если товар уже существует в БД (по URL) — просто подписывает пользователя на него
   - Если товар новый — создает его и подписывает пользователя
   - Если пользователь уже подписан на этот товар — возвращает ошибку

2. Просмотр списка: каждый пользователь видит только свои товары

3. Удаление товара:
   - Отписывает пользователя от товара
   - Если это был последний подписчик — удаляет товар и всю историю цен
   - Если есть другие подписчики — товар и история остаются

4. Дата начала отслеживания: показывается дата подписки конкретного пользователя (не дата создания товара)

Сценарии для тестирования:
- Пользователь A добавляет товар X
- Пользователь B добавляет тот же товар X (должен подписаться на существующий)
- Пользователь A видит товар X в своем списке
- Пользователь B видит товар X в своем списке
- Пользователь A удаляет товар X (товар остается в БД, т.к. есть подписчик B)
- Пользователь B удаляет товар X (товар полностью удаляется из БД)
- Пользователь A пытается добавить товар X повторно (должна быть ошибка)
- Даты начала отслеживания у разных пользователей должны различаться





Реализованные улучшения

  1. Добавлен дебаг-режим

  - Новая переменная окружения DEBUG_CAPTCHA в config.py
  - При DEBUG_CAPTCHA=1 — бот ждёт решения капчи до 60 секунд
  - По умолчанию (продакшн) — сразу закрывает браузер и возвращает None

  2. Human-like поведение (_human_like_behavior)

  - Случайный скроллинг вниз (300-800px)
  - Скроллинг обратно вверх (100-300px)
  - Случайные движения мыши по viewport
  - Случайные паузы между действиями

  3. Расширенные stealth-скрипты

  - Переопределение navigator.platform, hardwareConcurrency, deviceMemory
  - Реалистичные параметры screen (1920x1080)
  - Добавлены фейковые плагины Chrome (PDF Plugin, Native Client)
  - Переопределение getBattery API
  - Удаление следов автоматизации через CDP

  4. Улучшенная логика работы

  - Установка реалистичного viewport (1920x1080)
  - Имитация поведения на главной странице перед переходом к товару
  - Случайные паузы (1-3 секунды) между действиями
  - Имитация поведения перед парсингом данных
  - Быстрый выход при обнаружении капчи (в продакшн-режиме)

  5. Функция проверки капчи (_check_captcha)

  - Централизованная проверка по ключевым словам
  - Поддержка русских и английских вариантов

  Как использовать

  Продакшн (по умолчанию):
  # Капча → сразу выход, повторная попытка
  python run_bot.py

  Дебаг-режим:
  # В .env добавить:
  DEBUG_CAPTCHA=1

  # Или запустить с переменной:
  DEBUG_CAPTCHA=1 python run_bot.py

  - Открывает браузер с интерфейсом для ручного решения капчи
  - После успешного решения:
    - Отключает maintenance mode
    - Отправляет уведомление всем пользователям о восстановлении работы
    - Возобновляет обработку очереди
